我们先为项目添加了一项小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以配合组织现有的工作流程，帮助我们用正确的方法构建所需功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：先从议题开始构建新功能，确认代码有效且功能行为符合预期，最终将更改成功合并到项目中。

> [!NOTE]
> 后续功能工作流程会继续使用同一个会话。实际工作中，不同类型的文件通常会使用不同会话或 PR；本工作坊会简化流程，以便专注于核心概念。

本课将：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

后续课程会继续更新存储库说明、自定义现有 `quality-checks` 技能、添加 MCP 验证、创建 QA 智能体，并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访客需要按类别和发行商筛选游戏。积压议题描述了功能，但多个类别如何组合等细节需要在编码前达成共识。你将使用 Plan 模式明确这些决定，然后授权 Autopilot 在限定范围内实现。

## 背景

将 AI 编码智能体引入开发流程，不会改变基本原则。事实上，这些原则变得更重要了！大多数开发者遵循的流程大致如下：

1. 打开已创建的议题，查看需要完成的工作。
2. 制定构建计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述步骤类似。

遵循这种标准方法，可以确保 AI 生成的代码满足要求，并经过与手写代码相同的审查流程。

## 会话模式

**会话模式**决定智能体拥有多大自主权。可以通过提示字段下方的下拉菜单设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作——编写代码、运行测试并迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实施。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已创建的议题，无需再创建一个。
2. 选择 **New session**，并选择基于更新后 `main` 创建的 **new working tree**。

    ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果这些命令能在终端中运行，但在会话中无法运行，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装它。

## 规划筛选功能

规划让你有机会在 Copilot 编写代码前审查方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并对照议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改及测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。

计划应使用项目现有工具执行 lint、单元测试、E2E 测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准前先请求修改不符合预期的计划，并保留议题 URL 和已确定的说明，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。确认当前模式指示器显示 **Autopilot**，不要假设批准操作会自动切换模式。

Copilot 将开始实现功能！它会按照既定计划逐步推进，生成代码并运行测试。

> [!NOTE]
> 批准后可能立即开始实现，因此应先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也需要在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能的实现和测试。
2. 对照议题和已批准的说明检查结果，包括多个类别与发行商的组合。检查更改是否遵循现有存储库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的结果。跳过的检查不能算通过。
4. 接受实现前，修复失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览，也可能复用本地服务器；确保被测服务器属于此工作树，而不是之前课程中的工作树。

## 体验新功能

代码看起来没问题，但它能运行吗？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，请 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与之匹配。清除筛选后，选择一个发行商并确认结果与之匹配。
4. 同时应用类别和发行商筛选，并对照议题和已批准的计划检查结果。如果支持多个类别，请验证约定的组合行为。
5. 尝试没有匹配游戏的筛选组合并检查空状态。清除或重置筛选条件，确认完整列表恢复。
6. 完成后，使用以下提示请 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```
